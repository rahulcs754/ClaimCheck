Does the PR do what it says?

AI agents write confident PR summaries: "added tests", "no breaking changes", "handled errors". ClaimCheck checks each claim against the real diff and comments only on the ones that are not true.

Why

Agents say "done" too early

Developers report agents that claim tests or fixes they never wrote. Reviewers often trust the summary.

Review is the bottleneck

Knowing which claims are false tells a reviewer exactly where to look first.

Quiet by default

No comment when every claim matches. One comment per PR, updated on each push or edit.

No AI, nothing leaves CI

Plain rules over git diff. Fast, free and the same answer every time.

How to use it

  1. Add the workflow .github/workflows/claimcheck.yml: 
    on:
  pull_request:
    types: [opened, edited, synchronize, reopened]
permissions: { contents: read, pull-requests: write }
jobs:
  claimcheck:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: rahulcs754/claimcheck@main
  2. Open a PR. If a claim does not match the diff, ClaimCheck comments. Fix the code or the text and the comment turns ✅.
  3. Optional: set fail-on-mismatch: true to block the merge, or run npx github:rahulcs754/claimcheck --body-file pr.md from your agent before it opens the PR.

What it checks

Tests added

A test file has new lines. New .skip or .only is flagged.

No breaking changes

No exported name removed. Changed function params are flagged.

Errors handled

New try/catch, .catch(), throw or error checks.

Docs and changelog

README, docs, doc comments, CHANGELOG or changesets changed.

No new dependencies

package.json, requirements.txt, go.mod and Cargo.toml.

Code hygiene

No new any, @ts-ignore, console.log, TODOs; migrations; "one-line fix" size.
